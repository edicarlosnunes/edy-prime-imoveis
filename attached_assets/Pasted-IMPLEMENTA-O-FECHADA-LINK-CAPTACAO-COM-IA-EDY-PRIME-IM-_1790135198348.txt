IMPLEMENTAÇÃO FECHADA — LINK_CAPTACAO COM IA
EDY PRIME IMÓVEIS

OBJETIVO

Implementar no projeto atual da Edy Prime Imóveis o fluxo inteligente LINK_CAPTACAO, utilizando a estrutura existente e integrando o resultado à Ficha Única já implementada.

IMPORTANTE:
Esta tarefa NÃO é redesign.
NÃO reconstruir a Ficha Única.
NÃO alterar o site institucional.
NÃO publicar.
NÃO fazer deploy.
NÃO alterar Meta, WhatsApp ou integrações externas.
NÃO criar funcionalidades fora deste escopo.
NÃO fazer refatoração ampla do projeto.
NÃO substituir arquitetura existente sem necessidade.

Antes de alterar código, inspecione SOMENTE os arquivos, rotas, modelos e APIs diretamente relacionados a:
- LINK_CAPTACAO
- owner_intake_links
- formulário público /captacao/:token
- proprietários/owners
- imóveis/properties/property_captures
- Ficha Única
- corretores/angariadores
- anexos/fotos/documentos

Reutilize a estrutura existente sempre que possível.

==================================================
1. ENTRADA
==================================================

Manter o gerador genérico já existente em:

/admin/captacao/link

O link não deve exigir previamente nome ou telefone.

Cada utilização válida do link deve iniciar/continuar uma CAPTAÇÃO INDEPENDENTE.

Origem obrigatória:

LINK_CAPTACAO

O token bruto não deve ser persistido se a implementação atual já utiliza hash seguro.

Não enfraquecer a segurança existente.

==================================================
2. EXPERIÊNCIA PÚBLICA
==================================================

Evoluir /captacao/:token para uma conversa guiada por IA.

Não transformar a interface em um formulário longo disfarçado.

A experiência deve:
- apresentar uma pergunta principal por vez;
- aceitar texto natural;
- aproveitar várias informações fornecidas na mesma mensagem;
- salvar dados válidos antes de avançar;
- nunca perguntar novamente informação que já esteja registrada;
- permitir correções;
- permitir "não sei";
- manter progresso da sessão quando tecnicamente seguro;
- calcular a próxima pergunta pelos dados que ainda faltam, não apenas por um contador fixo.

Primeira identificação:

"Você é:
1 — Proprietário
2 — Locador
3 — Corretor"

Perfis internos:
PROPRIETARIO
LOCADOR
CORRETOR

==================================================
3. REGRAS GERAIS DA IA
==================================================

A IA deve interpretar linguagem natural e mapear somente informações com confiança suficiente.

Exemplo:

"É um apartamento de 2 quartos, uma suíte, 2 banheiros, uma vaga, 78 metros e fica no Canto do Forte."

Deve preencher, quando compatível com o schema existente:
tipo = apartamento
quartos = 2
suites = 1
banheiros = 2
vagas = 1
area = 78 m²
bairro = Canto do Forte

Depois NÃO perguntar novamente esses dados.

REGRAS:

- Resposta vazia não avança campo obrigatório.
- Campo opcional pode ser pulado.
- "0" significa inexistente/zero quando zero for resposta válida.
- "NÃO SEI" significa desconhecido.
- NUNCA converter NÃO SEI em zero.
- Não inventar informação.
- Não presumir preço.
- Não presumir documentação regular.
- Não presumir endereço.
- Não presumir característica.
- Resposta ambígua deve gerar pergunta curta de esclarecimento.
- Usuário pode dizer "corrigir", "errei", "voltar" ou equivalente.
- Correção deve alterar somente a informação correspondente.
- Não reiniciar toda a captação para corrigir um campo.
- Uma mensagem pode preencher vários campos.
- Dados espontâneos devem ser aproveitados.
- Cada sessão deve permanecer isolada das demais.
- Nunca misturar dados de usuários simultâneos.

==================================================
4. FLUXO PROPRIETÁRIO
==================================================

Após PROPRIETARIO:

coletar:
- nome completo;
- telefone/WhatsApp;
- e-mail opcional.

CPF/CNPJ NÃO deve bloquear a captação.
Não exigir CPF/CNPJ neste fluxo inicial.

Antes de criar novo proprietário:
procurar cadastro existente utilizando os identificadores seguros já suportados pelo projeto, especialmente telefone quando essa for a regra atual.

Se existir:
vincular.

Se não existir:
criar/preparar novo proprietário conforme arquitetura existente.

Um proprietário pode possuir vários imóveis.

Não criar proprietário duplicado apenas porque existe outro imóvel.

Perguntar finalidade:

VENDA ou LOCACAO.

Não existe "compra" neste fluxo.

Depois:
- tipo do imóvel;
- endereço;
- características condicionais;
- valores;
- situação;
- documentação;
- comodidades;
- fachada;
- revisão.

==================================================
5. FLUXO LOCADOR
==================================================

Após LOCADOR:

finalidade deve ser automaticamente:

LOCACAO

Não perguntar "venda ou locação".

Coletar:
- nome completo;
- telefone/WhatsApp;
- e-mail opcional.

Aplicar a mesma regra de deduplicação de proprietário.

Depois utilizar o mesmo motor de imóvel:
- tipo;
- endereço;
- características;
- valores;
- situação;
- documentação;
- comodidades;
- fachada.

Para locação coletar, quando aplicável:
- valor mensal pretendido;
- condomínio;
- periodicidade;
- IPTU;
- periodicidade;
- outras despesas existentes no schema;
- ocupado/desocupado;
- disponibilidade;
- mobiliado/não mobiliado quando aplicável;
- disponibilidade para visita;
- informação operacional de acesso/chaves quando houver campo apropriado.

Garantia locatícia:
permitir registrar informação/preferência quando houver destino apropriado, como:
- caução;
- seguro-fiança;
- fiador;
- título de capitalização;
- outra;
- a definir/não sei.

NÃO inventar política comercial da Edy Prime.

==================================================
6. FLUXO CORRETOR
==================================================

Após CORRETOR:

primeiro identificar O CORRETOR:
- nome;
- telefone/WhatsApp;
- CRECI quando aplicável;
- e-mail opcional.

Se existir corretor compatível no CRM:
vincular.

Evitar duplicação desnecessária.

Depois identificar separadamente O PROPRIETÁRIO:
- nome;
- telefone/WhatsApp;
- e-mail opcional.

REGRA CRÍTICA:

DADOS DO CORRETOR NUNCA PODEM SER GRAVADOS COMO DADOS DO PROPRIETÁRIO.

Manter entidades/vínculos separados.

O corretor deve ficar associado como responsável/angariador da captação quando a estrutura existente suportar esse vínculo.

Depois perguntar:

VENDA ou LOCACAO.

Em seguida utilizar exatamente o mesmo motor compartilhado de imóvel.

Não criar um segundo questionário independente apenas para corretor.

15. PERSISTÊNCIA E RETOMADA
==================================================

Garantir que:
- cada utilização tenha sessão/captação independente;
- resposta válida seja persistida antes de avançar;
- refresh não misture sessões;
- abandono não corrompa dados;
- retomada segura continue do primeiro dado realmente faltante;
- duas pessoas usando links simultaneamente não compartilhem estado;

Não depender exclusivamente do histórico textual da interface para conhecer o estado.

O estado persistido deve ser a fonte confiável para decidir a próxima pergunta.
